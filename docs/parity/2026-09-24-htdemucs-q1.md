# Q1: HTDemucs parity, 2026-09-24

Replication cell Q1 from `docs/audit/2026-09-24-audit-and-plan.md`.

## Stamp

- charon: commit `0435a99`, `cargo build --release --example separate`,
  default features (`ort-backend`). ort `=2.0.0-rc.13`, which links
  ONNX Runtime 1.28.0, CPU execution provider.
- Model: `htdemucs.onnx` from `StemSplitio/htdemucs-onnx`, SHA-256
  `68d0bf16428ef66e692cdff8a9ccf28f1ef3f69440d57e58605a4cc55fcc5e74`.
- Reference: demucs 4.1.0 (PyPI), torch 2.14.0, CPU,
  `demucs.api.Separator("htdemucs", shifts=0, overlap=0.25, split=True)`.
- ORT port: `tools/parity/reference.py onnx`, onnxruntime 1.30.0.
- Host: Apple M4 Pro, 24 GB, macOS 26.6.

## Input

Synthetic stereo mixes from `tools/parity/make_mix.py`: float32, 44.1 kHz,
5 s, 20 s and 31.3 s. Together they cover a single short segment, several
segments, and a partial last segment. **This is not real music. Separation
quality was not measured.**

## Result

Criterion: max |diff| <= 1e-3 against PyTorch Demucs on every stem. **PASS.**

charon vs PyTorch demucs 4.1.0:

| mix | stem | max\|diff\| | agreement SDR (dB) |
|---|---|---|---|
| 5 s | drums / bass / other / vocals | 1.03e-4 / 1.00e-4 / 3.78e-5 / 4.31e-5 | 80.1 / 84.1 / 88.1 / 66.8 |
| 20 s | drums / bass / other / vocals | 7.99e-5 / 1.74e-5 / 7.33e-5 / 1.13e-6 | 88.7 / 88.9 / 90.0 / 68.6 |
| 31.3 s | drums / bass / other / vocals | 1.20e-4 / 2.75e-5 / 1.00e-4 / 1.50e-6 | 88.7 / 88.6 / 89.9 / 68.6 |

charon vs ORT port of `apply_model` (same ONNX file): max |diff| at most
1.95e-6 on every stem and mix, so the Rust plumbing, chunking and
normalization are exact up to float rounding. The ORT port shows the same
differences against PyTorch as charon does (for example 5 s drums:
1.04e-4 vs 1.03e-4), so the remaining gap comes from the ONNX export, not
from charon.

Agreement SDR is `10*log10(sum(ref^2) / sum((ref - est)^2))` over the
whole signal. Vocals score lower because the synthetic mixes contain
little the model assigns to vocals, so the reference energy is small.

## Side observation (not a benchmark)

Peak RSS (`/usr/bin/time -l`) of the example binary: 3.8 GB for 5 s,
5.4 GB for 31.3 s. Wall time: 3.1 s for 5 s, 5.3 s for 31.3 s, including
model load. Measured once each, with no repetition and no warm-up.
Profiling is Phase C work.
